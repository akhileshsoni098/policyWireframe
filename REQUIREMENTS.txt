PART 2 — POLICY VERSIONING (snapshot + diff)  (doc Sec 12)
================================================================================
GOAL: Every policy carries a version number; completed transactions create a
      new version snapshot; user can view any version and a field-level diff
      vs the current version.
Approach chosen: "Snapshot + diff view" (lightweight; NOT a full immutable
journal).

----------------------------------------------------------------------
2.1  Add version fields to the quote record
----------------------------------------------------------------------
File: app.js — QUOTES seed (line ~16)
Optional fields (initialised by helpers, not seeded manually):
      q.version        = 1                     (int)
      q.versionHistory = []                    (array of snapshots)
Provide a helper used everywhere:
      function ensureVersioning(q) {
        if (!q.version) q.version = 1;
        if (!Array.isArray(q.versionHistory)) q.versionHistory = [];
      }

2.2  snapshotQuote(q) helper
----------------------------------------------------------------------
File: app.js — add near helpers (line ~594)
Captures the CURRENT field values into a plain object:
      {
        insuredName, fein, lob, coverage, limit, deductible,
        effective, expiration, premium, basePremium, modFactor,
        scheduleCredit, slaTax, stampingFee, ratingBasis,
        billingPlan, paymentMethod
      }
Return the object. (Keeps snapshot small; add fields if needed later.)

2.3  bumpVersion(q, type, summary) helper
----------------------------------------------------------------------
File: app.js — add near snapshotQuote
Logic:
  1. ensureVersioning(q).
  2. current = snapshotQuote(q)  (the state BEFORE change if called first)
     => call bumpVersion BEFORE mutating q, OR snapshot before+after.
  3. changedFields = compare snapshot vs current quote after change
     (field names whose value changed).
  4. q.versionHistory.push({
       version: ++q.version,            // new version number
       timestamp: ISO now,
       type: type,                      // 'ISSUE' | 'RENEWAL' | 'ENDORSEMENT' | 'EXPIRATION' | ...
       summary: summary,
       changedFields: changedFields,
       snapshot: <snapshot object of post-change state>
     })
Note: to compute changedFields reliably, pass both the pre-snapshot and the
post-snapshot, or capture pre-snapshot first then call after mutation.
Recommended pattern per change site:
       const pre = snapshotQuote(q);          // before mutation
       ... mutate q ...
       const post = snapshotQuote(q);         // after mutation
       const diff = fieldsChanged(pre, post);
       q.versionHistory.push({ version:++q.version, ..., changedFields:diff, snapshot:post });

2.4  fieldsChanged(pre, post) helper
----------------------------------------------------------------------
File: app.js — add near snapshotQuote
Return array of keys where pre[k] !== post[k].

2.5  Hook version bump into every state-changing flow
----------------------------------------------------------------------
File: app.js — one call each:
a) confirmIssue()        (line ~2864)  -> type 'ISSUE'        (first version, version 1)
b) acceptNotice() renewal branch (line ~2632) -> type 'RENEWAL'
c) processEndorsementRequest() APPROVED path (line ~1376) -> type 'ENDORSEMENT'
d) expirePolicy()        (line ~2711)  -> type 'EXPIRATION'
For (b)/(c)/(d): capture pre-snapshot, apply existing mutations, then bump.
Do NOT bump on: reject/decline, notices, reinstatement is optional (can bump
with type 'REINSTATEMENT' — recommended for consistency).
